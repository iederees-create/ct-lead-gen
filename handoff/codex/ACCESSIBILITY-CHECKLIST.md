# Accessibility Checklist

Use this after the final UI merge.

| Area | Check | Status |
| --- | --- | --- |
| Semantic headings | One `h1`; headings descend logically through page sections | Pending |
| Landmarks | Header, nav, main, footer are present | Pending |
| Skip link | Add skip link if fixed navigation or long page sections impede keyboard users | Pending |
| Form labels | Every planner input/select/textarea has a visible label | Pending |
| Field grouping | Related radio/checkbox controls use `fieldset` and `legend` or equivalent ARIA | Pending |
| Error messages | Errors identify the affected field and are announced to assistive tech | Pending |
| Keyboard operation | All nav, planner, copy, print, download, reset, WhatsApp, and email controls work without a mouse | Pending |
| Visible focus | Focus indicators are visible against all backgrounds | Pending |
| Reduced motion | Animations/transitions respect `prefers-reduced-motion` | Pending |
| Contrast | Text, buttons, focus rings, and disabled states meet WCAG contrast expectations | Pending |
| Modal/dialog behavior | If any modal exists, focus is trapped, labelled, and returned on close | Pending |
| Mobile accessibility | Controls are large enough, text does not overlap, and horizontal scroll is avoided | Pending |
| Screen reader text | Icon-only controls have accessible names | Pending |
| Summary updates | Quote summary changes are discoverable without disruptive live-region spam | Pending |
| Disabled budget mode | Disabled estimate state is explained in text, not only color | Pending |
